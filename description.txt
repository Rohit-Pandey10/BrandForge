1. EXECUTIVE OVERVIEW
--------------------------------------------------------------------------------
The `server/` directory contains the Node.js/Express backend that powers the
Brand Builder platform. Its primary mission is to conduct adaptive, Socratic-
style brand discovery interviews with startup founders and synthesize the
resulting dialogue into a production-grade Brand Kit (including strategy,
archetypes, voice/tone rules, CSS design tokens, typography pairings, and
launch copy/manifestos).

The backend features:
- Dual-Provider LLM Engine: Groq (Llama 3.3 70B Versatile) as primary provider
  with seamless automatic failover to Google Gemini 2.5/3.x Flash models.
- Domain-Adaptive Intelligence: Dynamic classification of founder pitches into
  domains (Hospitality/Dining, Fashion/Apparel, Developer Tools/SaaS, Wellness,
  Career/HR, Creative Agencies) with strict anti-cliche/anti-jargon enforcement.
- Deterministic Mock Safety Net: Comprehensive, offline mock generation engine
  that guarantees 100% operational uptime and immediate local testing even if
  network connectivity or API quotas fail.
- Layered Architecture: Strict separation of concerns (Routes -> Controllers
  -> Services -> Prompts & Data -> LLM/SDK Clients).

Description:
  Declares the HTTP endpoints for the brand creation pipeline and maps each
  route to its dedicated controller function.
Exposed Endpoints:
  1. `POST /api/interview/start` -> Maps to `handleStartInterview`

  2. `POST /api/interview/next` -> Maps to `handleNextQuestion`
     Dynamically inspects conversational history to generate the next probing
     question with 3 clickable suggested answer options and rationale.
  3. `POST /api/interview/compile` -> Maps to `handleCompileBrandKit`
     Compiles user answers and interview transcript into a structured Brand Kit.

FILE: controllers/interviewerController.js
Location: server/controllers/interviewerController.js
Role: HTTP Request Validation & Service Orchestration
--------------------------------------------------------------------------------
Description:
  Acts as the thin controller layer between HTTP requests and the business logic
  services. Contains zero inline prompts and zero mock data.
Key Responsibilities:
  1. Input Validation:
     - `validateHistory(history)`: Ensures message histories are valid arrays
       with maximum 50 turns and proper `{ role, content }` objects.
     - Validates that `initialPitch` is a non-empty string.
  2. Request Handlers:
     - `handleStartInterview(req, res)`: Extracts initial pitch, invokes
       `interviewService.generateInterviewBatch()`, and returns `{ questions }`.
     - `handleNextQuestion(req, res)`: Validates history payload, delegates to
       `interviewService.generateNextQuestion()`, and returns Socratic question.
     - `handleCompileBrandKit(req, res)`: Handles both modern `{ qaPairs, initialPitch }`
       payloads and legacy `{ history }` arrays, delegates to
       `compilerService.compileBrandKit()`, and returns complete Brand Kit.
  3. Re-exports:
     - Re-exports validation schemas (`questionSchema`, `batchQuestionSchema`,
       `brandKitSchema`) and domain helpers (`classifyDomain`, `isFamilyIntent`)
       for backward compatibility with integration tests.

FILE: services/interviewService.js
Location: server/services/interviewService.js
Role: Socratic Question Generation & Schema Enforcement
--------------------------------------------------------------------------------
Description:
  Core business service responsible for formulating probing, high-signal
  Socratic questions that force founders to articulate their brand identity.
Key Features & Functions:
  1. `batchQuestionSchema`: JSON Schema enforcing the structure of upfront
     batch questions (id, stageLabel, question, suggestedAnswers, reasoning).
  2. `questionSchema`: JSON Schema enforcing single-round question outputs
     (currentRound, question <25 words, suggestedAnswers <6 words each,
     reasoning, stageLabel, isComplete flag).
  3. `generateInterviewBatch(initialPitch)`:
     - Detects business domain using `classifyDomain()`.
     - Checks for family dining intent via `isFamilyIntent()`.
     - If LLM is configured, generates 7 targeted discovery questions upfront
       using `llmClient.generateStructuredJson()`.
     - Automatically falls back to `mockEngine.getMockBatch()` on any LLM or
       network failure.
  4. `generateNextQuestion(history)`:
     - Determines current interview round and user context from transcript.
     - If round >= 3, sets `isComplete: true` allowing instant synthesis.
     - Calls LLM or falls back to `mockEngine.getMockQuestion()`.

FILE: services/compilerService.js
Location: server/services/compilerService.js
Role: Brand Kit Synthesis & Design Token Engine
--------------------------------------------------------------------------------
Description:
  Takes founder interview responses and synthesizes a complete, mathematically
  and aesthetically cohesive Brand Kit.
Key Features & Functions:
  1. `brandKitSchema`: Comprehensive JSON schema defining the required brand kit:
     - `brandStrategy`: brandName, tagline, mission, targetAudience,
       coreValueProposition, antiHero, differentiator.
     - `voiceSystem`: archetype, tone list, dos, donts, vocabularyWords.
     - `visualTokens`:
       * `palette`: Array of 5 tokens (primary, secondary, accent, surface, text)
         with valid hex codes and functional names.
       * `typography`: headingFont, bodyFont, googleFontsUrl, rationale.
       * `stylePhilosophy`: Visual language description.
       * `borderCurvature`: Border radius specifications.
     - `launchContent`: heroHeadline, heroSubheadline, callToAction,
       manifesto (full-length prose), elevatorPitch, socialHooks.
  2. `compileBrandKit(payload)`:
     - Normalizes incoming payloads (extracts Q&A pairs, initial pitch, answers).
     - Formulates synthesis prompts with domain anti-jargon instructions.
     - Dispatches request via `llmClient.generateStructuredJson()`.
     - Gracefully falls back to `mockEngine.getMockBrandKit()` on failure.

--------------------------------------------------------------------------------
Description:

     - Fallback Route (Gemini): Uses `@google/genai` with `responseSchema` and
       `responseMimeType: 'application/json'` to guarantee schema compliance.
     - Throws clean error if neither provider is reachable or configured.
